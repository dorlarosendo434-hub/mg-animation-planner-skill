# 完整提示词与交付模板

只在编写最终视频提示词或交付素材包时读取本文件。

## 完整提示词骨架

用用户主题和最终素材编号替换占位内容，不保留方括号。

```text
【请制作一支中文科普短片《[片名]》MG动画。

画布规格：[16:9/9:16/4:3/3:4/1:1]，[像素尺寸]，时长约[时长]。说明安全边距与裁切限制。

设计决策：说明本次为自动适配、用户选择或自定义；写明主风格、可选辅助风格和选择理由。

全片结构：说明完整场景、透明垫图、真实影像和纯MG的组合方式，以及整体节奏。

核心表达：写清最终知识结论、概率或边界条件，列出不得夸张的说法。

图片引用规则：上传素材命名为“图片01.png”至“图片NN.png”。提示词中的“图片NN”必须调用对应文件。

视觉风格：色彩、材质、人物风格、空间感、禁止项。

文字动效：标题字体、正文字体、关键词、可用动效、不可用动效。

旁白与背景音乐：声音气质、完整配乐的起承转合、音效范围。

转场规则：指定与内容机制一致的转场，限制无意义炫技。

分镜脚本：

片段0，[名称]，约[时间]。
画面：说明图片编号、素材类型、位置、镜头、首尾状态和连续性。
文字动效：写出需要实际显示的中文。
旁白及字幕：写出完整句子。

片段1……

片尾要求：说明最后画面、停留时间、音乐收束和禁止的品牌元素。】
```

## 每个片段的最低完整度

每段都回答：

1. 用哪张图；
2. 图放在哪里、如何进入；
3. 镜头或MG元素怎么动；
4. 屏幕上出现什么文字；
5. 旁白说什么；
6. 如何转到下一段。

只写“画面炫酷”“卡片飞入”不算完成。

## 旁白规则

- 开头先提出反常识或差异，不先下定义；
- 一句话只承担一个新结论；
- 机制用因果链表达，避免名词堆砌；
- 概率机制使用“可能”“更容易”“估计”等词，不写成必然；
- 结尾给观众一个可记忆结论或行动出口；
- 字幕与旁白一致，专业名词首次出现时给简短解释。

## 推荐交付结构

```text
[主题]_MG素材包/
├─ 00_完整提示词.md
├─ 00_旁白字幕稿.md
├─ 00_图片编号清单.md
├─ 00_科学依据与表达边界.md（需要事实核验时）
├─ 00_垫图总览.png（可选）
├─ 图片01.png
├─ 图片02.png
└─ ...
```

另提供同名ZIP压缩包。

## 交付前检查

- 主题、标题、旁白和画面讲的是同一个机制；
- 画幅与主/辅助风格已经记录，且尊重用户明确选择；
- 画幅和所有完整场景尺寸一致；
- 图片从01连续编号，无缺号、重号或第二套编号；
- 提示词引用的每张图片都存在；
- 每张图片都被提示词使用，或在清单中标记为备用；
- 透明图确有Alpha；完整场景为不透明；
- 首尾帧配对关系写入清单和提示词；
- 字幕安全区、Logo限制、裁切限制写明；
- 用户能只靠文件夹与提示词继续制作，不依赖聊天记录。
